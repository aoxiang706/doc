1. 概述与目标

1.1 背景

PTZ（光电转台）在远距离工作时视场角极小（<1°），不具备主动探测能力，必须依赖雷达等设备提供引导角度信息。雷视标定的核心目的是：通过对比雷达检测角度与PTZ实际锁定角度的差异，求解并修正两者之间的安装偏差（外参），从而提高雷达→PTZ引导的精度。

前期已完成四面阵近程雷达的标定功能。中程雷达与近程雷达在探测距离、角度精度、波束特性上存在显著差异，需要针对中程雷达的特点对标定流程和算法进行适配与优化。

1.2 标定目标

维度 说明
待标定外参 yaw_offset（方位偏差）、pitch_offset（俯仰偏差）、roll_offset（横滚偏差）、height_offset（高度偏差）
精度指标 方位/俯仰残差均值 < 0.5°，方差 < 0.3° (目标值)
支持拓扑 机扫中程雷达 + PTZ；四面阵中程雷达 + PTZ
C2交互 与近程标定流程统型，复用 0x71 / 0x91 / 0x92 / 0x93 / 0x95 消息，新增 0x9A 统合启停/查询

3. 端到端标定流程现状

3.1 用户设置初值 (0x71)

流程：C2 → alink_set_mark_param_new() → 写入 SQLite (write_global_calibration) + 写入 YAML (g_hostDevCfgApi.updateBySn) → ros_app_cmd_set(21, 1) 通知自标定模块 → 自标定模块调用 init_alg() 读取初值 → 发布 UserCalibState → 嵌入式上报 C2。

当前代码位置：alink_track.cpp:667-714

参数内容：heading（朝向角）、longitude、latitude、altitude、rolling、pitching、relativeHeight

🔴 发现的问题

  1. 双写冗余：同时写入 SQLite 和 YAML，注释中提到"以后不用这个表了，统一用yaml，短期暂时不删除"——但两年后仍未清理
  2. SN硬编码：strcpy(list.sn, "SRP100") 硬编码了设备SN，不支持多设备场景
  3. 缺少参数校验：收到的坐标参数没有有效性检查（如经纬度范围、海拔合理性）

3.2 启动标定 (0x94 / 0x9A)

需求：使用新的 0x9A 消息统合启动、停止、添加/删除标定方位角、查询历史标定结果。

当前代码：仍使用旧的 0x94 (user_start_radar_calibration)，只支持"启动标定"功能。

C2 → 0x94(sn + reserve) → alink_track.cpp:952
  → ros_app_cmd_set(CMD_ID_LOCAL_CALIBRATION, STATE_CODE_CALIBRATION_USER_MODE_START)
  → 自标定模块检查雷达/PTZ在线 → CALIB_STATE_IDLE
  → 嵌入式收到IDLE后 → ros_app_calib_radar_info(calibration_sn) 发送SN给引导模块
  → 引导模块转动PTZ至雷达法线角度 → 应答 PTZ_ARRIVED
  → 自标定模块切换至 CALIB_STATE_PTZ_ARRIVED

🔴 发现的问题

  1. 0x9A 未实现：需求文档定义了 0x9A 消息（含cmd=1启动/2停止/3添加方位/4删除方位/5查询历史），但代码中完全不存在
  2. 0x96 功能有限：当前 0x96 只是查询已有标定SQL数据，不支持按方位角添加/删除
  3. 无"标定方位角"概念：中程雷达可能需要按方位分段标定（0°/90°/180°/270°等），但当前代码没有方位角管理逻辑

3.3 PTZ锁定无人机

流程：

  1. 自动锁定模式 (默认)：PTZ自动检测并锁定无人机 → 引导模块应答 PTZ_TRACKING_FINISHED
  2. 手动锁定模式 (0x91 Request=4)：C2切换到手动模式 → 引导模块释放目标、启动AI检测 → 用户在C2界面手点像素框 → C2下发 0x95 → 引导模块锁定指定像素目标
  3. 锁定确认/取消 (0x91 Request=1/2)：C2弹窗确认锁定的目标

当前代码位置：alink_track.cpp:996-1037 (radar_calibration_req)

🔴 发现的问题

  1. 0x91 处理不完整：需求定义了8种Request值，当前代码只实现了1-4，且：
    - Request=5（退出PTZ手动锁定）→ 返回 0xFF（未实现）
    - Request=6（标定结果取消）→ 缺失
    - Request=7（手动选择雷达目标）→ 缺失
    - Request=8（自动选择雷达目标）→ 缺失
  2. 映射关系错乱：代码中 Request=3 映射到 RESULT_CONFIRMED，但需求文档中 Request=3 是"视觉锁定目标确认"，Request=7 才是"标定结果确认"。新老定义有冲突。

3.4 雷达目标选择与采样

流程：
- 自标定模块切换到 CALIB_STATE_RADAR_MANUAL_SELECT 或自动选择模式
- 用户在C2选择雷达靶机目标 → 0x81 → 嵌入式转发
- 自标定模块将雷达原始目标与手选ID匹配 → 坐标转换到PTZ坐标系
- 结合PTZ锁定角度，计算雷达-PTZ角度偏差
- 按1Hz发布 CalibRadarPtzObjList (0x93) 给C2显示曲线

当前代码实现（在 ptz100_agx_fix 中）：
- ai_alg_calib() 作为标定主函数
- radarGuide_calib() 选择雷达目标
- 数据写入文件 radar_ptz_status.txt
- 采集完成后启动 mark_task 线程调用 mainAPI() 计算外参

🔴 发现的问题

  1. STATE_CODE_CALIBRATION_USER_MODE_RADAR_MANUAL_SELECT 未定义：需求文档引用了此状态码，但代码中不存在
  2. 雷达原始目标类型 0xE1 复用冲突：需求说新增 0xE1 用于雷达原始目标，但代码中 0xE1 已被 track_pkg_remote_id（遥控ID）和 HeartBeatHostStatus（心跳）复用
  3. 数据采样使用文件 I/O：ai_alg_calib() 每个采样点都 fopen/fprintf/fclose，在高频采样下存在性能和可靠性隐患
  4. 缺少中程雷达特化筛选：radar_2ptz_calib() 仅靠 alive >= 0 过滤，没有距离/速度/仰角/信噪比门限

3.5 标定完成与结果确认

流程：
- 采样达到阈值或超时 → 启动 mark_task 线程
- mainAPI() 从文件读取采样数据 → 分段、合并、去异常值 → 计算方位/俯仰偏差均值
- 结果通过 alink_upload_mark_result() 上报C2
- C2弹窗确认 → 0x91 Request=3 → RESULT_CONFIRMED
- 嵌入式将结果写入YAML

🔴 发现的问题

  1. 结果未持久化到SQLite：mark_task 计算完成后只上报C2，没有将 yaw_offset/pitch_offset 写入 radar_calibration 表
  2. 结果未实时应用：setPTZ0() 函数中没有加载标定偏差值进行修正
  3. 自标定模块与AI算法模块职责交叉：需求文档描述的流程由自标定模块（ROS节点）主导，但实际代码中标定逻辑在AI算法模块（ai_alg_calib），两个体系不一致

6. 核心算法分析

6.1 目标筛选 (radar_2ptz_calib)

文件：ptz100_agx_fix/src/srv/algs/ai_alg/guide.cpp:203-263

当前逻辑：

对所有雷达目标:
    if (alive >= 0):       // 唯一过滤条件
        加入 useful_obj

if useful_obj 只有1个:
    直接选定
else if 有多个:
    选择与当前锁定ID匹配的目标 (按 ptz_id 匹配)
    否则选择 alive 值最大（生存时间最长）的目标

🔴 问题

问题 影响 建议
仅靠 alive>=0 过滤 杂波、地物、车辆等非目标也会通过 增加距离范围(200m-5km)、速度门限(>2m/s)、仰角门限(>0°)等中程特化筛选条件
无RCS/SNR门限 低质量探测点影响标定精度 若雷达上报SNR/RCS，增加门限过滤
未使用目标分类信息 classification 字段未利用 仅选择 classification==无人机 的目标
多目标选择策略简单 可能误选非标定靶机 结合C2手选ID(0x81)做强关联，或要求标定时空域只有单一目标

6.2 引导采样 (radarGuide_calib)

文件：ptz100_agx_fix/src/srv/algs/ai_alg/ai_main.cpp:837-917

当前逻辑：

调用 radar_2ptz_calib 选取雷达目标
if 选取成功:
    记录雷达目标角度到全局变量 (target_horizatal_angle, target_pitching_angle, target_range)
    记录速度 (target_vx, target_vy, target_vz)
    （注意：setPTZ0 引导PTZ转向的代码被注释掉了）

数据采样在 ai_alg_calib() 的后半部分完成：

if mark_status == 1 且有雷达数据:
    写入 radar_ptz_status.txt:
        radar_azimuth, radar_elevation, range, vx, vy, vz,
        ptz_azimuth, ptz_elevation, timestamp, id, track_azimuth, track_elevation

🔴 问题

问题 影响 建议
setPTZ0 被注释掉 标定时不引导PTZ跟踪雷达目标，依赖PTZ自行AI检测锁定 标定时应该由雷达引导PTZ对准目标，或至少辅助引导
使用文件IO采样 高频写文件影响实时性；文件损坏则丢失所有数据 改为内存buffer采样，完成后一次性写入或直接在内存中计算
缺少采样质量评估 每个采样点都无条件记录 增加实时一致性检查：连续采样角度跳变>阈值时丢弃
record_time 超时机制不健壮 AI_MARK_COLLECT_DATA_TIMEOUT 从record_time开始计算，包含等待目标出现的时间 应从实际开始有效采样时计时

6.3 外参求解 (mainAPI / calib.cpp)

文件：ptz100_agx_fix/src/srv/algs/ai_alg/calib.cpp:59-521

当前算法流程：

1. 从文件读取 CSV 数据 (radar_azimuth, radar_elevation, range, ..., ptz_azimuth, ptz_elevation, ...)
2. 远离过程分段:
   - 按距离递增趋势分段
   - 相邻段角度跳变>阈值时切分
   - 计算各段方位/俯仰 vs 距离的斜率和截距
   - 合并相似段
   - 选择样本最多的段
   - 去除相邻帧角度差>1°的异常点
3. 靠近过程分段: (反向遍历，同样逻辑)
4. 合并远离/靠近两段数据
5. 计算方位/俯仰偏差:
   H_off = radar_azimuth - ptz_azimuth
   V_off = radar_elevation - ptz_elevation
6. 中值滤波: 排序后取中值
7. 阈值去异常: abs(偏差 - 中值) < f_TH(=10°)
8. 截尾均值: 取中间60%数据(20%-80%)求均值
9. 取反作为标定值: yaw_offset = -mean(H_off), pitch_offset = -mean(V_off)
10. 写入 calib.conf 文件

🔴 问题

问题 严重度 详细说明
仅求解yaw/pitch，无roll/height 高 需求要求4个外参(yaw, pitch, roll, height_offset)，但算法只计算2个
简单差值法，非旋转矩阵拟合 高 直接用角度差均值作为外参，忽略了roll引起的交叉耦合（方位偏差随俯仰角变化）
f_TH=10° 硬编码阈值 中 对于精标定场景，10°的异常阈值过大；应根据数据分布自适应
最少50个有效样本 中 硬编码 v_azimuth_off_valid_size < 50 返回失败，不可配置
文件读写作为数据接口 中 从文件读取CSV数据容易因格式错误崩溃（如 std::stof 抛异常）
分段合并逻辑复杂且无文档 中 分段+合并+筛选逻辑约200行代码，完全没有注释说明目的
无距离加权 中 远距离采样点角度误差较大，应给予较低权重
截尾均值比例固定 低 使用20%-80%截尾均值，比例不可调整
角度wraparound处理不完整 低 仅在偏差>180°时+-360°，但分段逻辑中可能遗漏

改进建议：外参求解算法

推荐的数学模型：

给定雷达目标在雷达坐标系下的方位角 (a_r)、俯仰角 (e_r)，以及 PTZ 实际锁定的方位角 (a_p)、俯仰角 (e_p)，建立模型：

$$
\begin{bmatrix} a_p \ e_p \end{bmatrix} = R(\Delta\text{yaw}, \Delta\text{pitch}, \Delta\text{roll}) \cdot \begin{bmatrix} a_r \ e_r \end{bmatrix} + \text{bias}
$$

对于小角度偏差，可简化为线性模型：

$$
a_p \approx a_r + \Delta\text{yaw} + \Delta\text{roll} \cdot \tan(e_r)
$$
$$
e_p \approx e_r + \Delta\text{pitch} + \Delta\text{height_offset} / d
$$

其中 (d) 是目标距离。使用加权最小二乘法求解：

$$
\min \sum_{i} w_i \left[ (a_{p,i} - a_{r,i} - \Delta\text{yaw} - \Delta\text{roll} \cdot \tan(e_{r,i}))^2 + (e_{p,i} - e_{r,i} - \Delta\text{pitch} - \Delta h / d_i)^2 \right]
$$

权重 (w_i) 可基于距离和SNR设置。
