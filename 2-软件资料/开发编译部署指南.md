# 软件开发编译打包指南

## 1. 下载源码

```bash
git clone https://adasgitlab.autel.com/ssg/ptz100_agx.git
cd ptz100_agx
git checkout develop
git pull
git submodule update --init --recursive
```

## 2. x86 服务器编译

在 x86 编译服务器上进行全量编译，适用于无本地交叉编译环境或需与 CI 一致的场景。

### 全量编译

1. SSH 登录 x86 编译服务器：`10.229.1.52`
2. 进入 `ptz100_agx` 源码目录
3. 执行编译脚本：

```bash
/home/autel/Downloads/build_agx.sh ptz100_agx
```

参数 `ptz100_agx` 为待编译的源码目录名。

### 个人编译容器

若仅需借用 AGX 编译环境时，可创建个人 Docker 容器。将容器名、挂载路径替换为个人路径后执行：

```bash
docker run -it \
  --name=<容器名> \
  --net=host \
  -v <宿主机目录>:/home/ \
  10.240.34.2:10000/cibuilder/srp100:v6 \
  /bin/bash
```

示例：

```bash
docker run -it --name=zyh_agx_test --net=host -v /home/a25175/share/zyh/:/home/ 10.240.34.2:10000/cibuilder/srp100:v6 /bin/bash
```

## 3. 本地开发板编译

### 全量编译

```bash
cd ros_ws
colcon build --parallel-workers 12
```

### 单包编译

```bash
cd ros_ws
colcon build --packages-select ptz100_ros
```

将 `ptz100_ros` 替换为目标包名即可。各 ROS 包位于 `ros_ws/src/` 下，例如 `ptz100_ros`、`sysmonit`、`nexus_gateway` 等。

## 4. 手动运行

> 注意：手动启动进程前，确认不与 monit 管理的进程冲突。可先访问 `http://<IP>:2812`（monit Web 页面）查看当前进程状态。

```bash
cd ros_ws
source install/setup.bash
ros2 run ptz100_ros ptz100_ros
```

## 5. 打包

### 5.1 CI 脚本一键编译打包（推荐）

仓库根目录执行 `build_ci.sh`，依次完成：子模块初始化 → `build_app.sh` 编译 → `pack_app.sh` 打包。

```bash
# 在仓库根目录执行
./build_ci.sh "${version}"

# 示例
bash build_ci.sh SRP_GE_FW_V1.0.0
```

- 不传版本号时使用 `build_app.sh` 默认版本。
- 产物路径：`config/tools/ota_tools/build_host/output/*.bin`


### 5.2 本地分步打包（主设备应用包）

已编译完成、仅需重新打包时：

```bash
cd config/tools/ota_tools/build_host
./pack_app.sh
```

需先编译再打包时：

```bash
cd config/tools/ota_tools/build_host
./build_app.sh --version SRP_GE_FW_V1.0.0
./pack_app.sh
```

### 5.3 综合 OTA 包（主设备 + 子设备）

```bash
cd config/tools/ota_tools/build_image
./pack_image.sh --version V1.0.0
```

将主设备、子设备软件包放入 `image/` 对应目录并填写 `pkg.meta.json`。

详细说明见 [build_host README](../../config/tools/ota_tools/build_host/README.md)、[build_image README](../../config/tools/ota_tools/build_image/README.md)。

## 6. 升级

## 7. 设备配置

AGX 现场调试与运维可通过 **monit**、**sysmonit Web** 或 **命令行** 完成进程管理与设备类型等配置。

### 7.1 本地 monit 登录

浏览器访问 monit Web 页面，查看各进程运行状态，并执行 start / stop / restart：

```
http://<IP>:2812
```

- 用户名：`admin`
- 密码：`monit`

### 7.2 本地 Web 登录

浏览器访问 sysmonit 运维仪表盘，登录后可进行系统概览、参数配置、进程管理等操作：

```
http://<IP>:12345
```

- 用户名：`admin`
- 密码：`monit`

### 7.3 手动设置设备类型

设备上也可通过命令行直接设置主/次设备类型。不传参数或参数不合法时，会打印可选值及当前配置：

```bash
setDeviceType                    # 查看可选值与当前配置
setDeviceType ssf200             # 仅设置主设备类型为 spotter ssf200
setDeviceType sentry ssf200      # 主设备(sentry) + 次设备(ssf200)
```

## 8. 上传代码

### 8.1 拉取并合并

```bash
git pull
git pull origin develop
git submodule update --recursive
git status
git submodule status
```

如有冲突，先用 vim 或 IDE 解决；差异较大的分支合并建议使用 Beyond Compare 等专业工具对比。

### 8.2 提交主仓库

```bash
git status
git add ./
git commit -m "修改说明"
git push origin develop
```

### 8.3 提交子仓库

以 `ros_ws/src/dhp100` 为例：

```bash
# 进入子仓库
git submodule status
cd ros_ws/src/dhp100
git status

# 暂存本地修改
git stash

# 切换分支并拉取
git checkout develop
git pull
git pull origin develop

# 恢复暂存
git stash pop

# 提交子仓库
git status
git add ./
git commit -m "修改说明"
git push origin develop

# 将子仓库新 commit 提交到主仓库
cd -
git status
git add ros_ws/src/dhp100
git commit -m "更新 dhp100 子模块"
git push origin develop
```
